## Ошибки и предложения

В Issue укажи платформу, версии приложения и ОС, шаги воспроизведения, ожидаемый
и фактический результат. Для звука — аудиовыход, формат и движение времени трека;
для сервера — его тип и версию. Пароли, подписанные URL и личные данные не публикуй.
Для уязвимостей используй [SECURITY.md](SECURITY.md).

## Изменения

1. Создай ветку от `main`; один PR решает одну понятную задачу.
2. Соблюдай стиль проекта: TypeScript strict, Swift 6, Kotlin, JS-зависимости через Bun.
3. Общие алгоритмы поиска текстов, ReplayGain и цвета обложки меняй согласованно
   на трёх платформах. При необходимости добавь сценарий в `shared/cases`.
4. Выполни относящиеся к изменению проверки из README. Для UI приложи скриншоты
   узкого и широкого экрана; для аудио — результат живой проверки воспроизведения.
5. В PR опиши проблему, итоговое поведение и команды с результатами проверки.

Не коммить сборки, `.env`, пароли, сертификаты, профили и ключи. Мок использует
публичные тестовые данные `test` / `demo`; свои данные в исходники подставлять не нужно.

Официальную подпись и выпуск выполняет сопровождающий. PR не должен публиковать релизы
или менять ключи обновлений. Для новой зависимости укажи лицензию и обнови уведомления.
Сохраняй уведомления об авторстве и не выдавай стороннюю сборку за официальную.
