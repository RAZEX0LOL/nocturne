# Работа с сервером

Протокол — OpenSubsonic (Navidrome). Проверяемая часть правил лежит в `shared/cases/credentials.json`
и `shared/cases/requests.json`; здесь то, что кейсами не выразить.

## Адрес сервера

HTTPS всегда. Обычный HTTP разрешён только для локальной сети: частные диапазоны IPv4
(10/8, 127/8, 169.254/16, 172.16–31, 192.168/16, 100.64–127), локальные IPv6 (::1, fe80:, fc, fd),
имена без точки, `.local`, `.home.arpa`, `localhost`. Адрес с логином, паролем, строкой запроса
или фрагментом отклоняется — такие ссылки почти всегда означают, что человек вставил не то.

Подпуть сохраняется: сервер за реверс-прокси на `https://host/navidrome` обязан работать.

## Подпись запроса

К каждому запросу добавляются `u`, `t`, `s`, `v=1.16.1`, `c=Nocturne`, `f=json`, где
`t = md5(пароль + соль)`, а соль — своя на каждый запрос. Пароль не передаётся ни в каком виде,
параметра `p` быть не должно. MD5 здесь — требование протокола, а не выбор: поэтому обычный HTTP и
запрещён везде, кроме домашней сети.

Плюс в значениях параметров кодируется как `%2B`, иначе сервер прочитает его как пробел.

## Ответы

Subsonic отвечает `HTTP 200` даже на ошибку, поэтому статус внутри тела важнее кода ответа:
`status: failed` — это ошибка. Сообщение сервера пользователю не показывается, вместо него — своя
формулировка («Неверный логин или пароль»), чтобы наружу не утекали подробности.

Ответ, который не разбирается как ответ Subsonic (HTML страницы входа прокси, посторонний JSON),
считается ошибкой, а не пустым результатом.

Необязательные поля действительно необязательные: альбом без исполнителя, жанра и года — нормальный
альбом. Длительность приходит дробной.

## Повторы

Чтения идемпотентны, поэтому оборванную связь переспрашиваем: всего три попытки с паузами 0,5 и
2 секунды (`shared/cases/retries.json`). Ответ самого сервера — неверный пароль, ошибка 500 — не
повторяется: второй раз он будет таким же.

## Запросы, которые использует приложение

Библиотека: `ping`, `getAlbumList2`, `getAlbum`, `getArtists`, `getArtist`, `getPlaylists`,
`getPlaylist`, `getStarred2`, `getGenres`, `search3`, `getSimilarSongs2`, `getTopSongs`,
`getArtistInfo2`, `getAlbumInfo2`, `getInternetRadioStations`.

Действия: `star`, `unstar`, `setRating`, `scrobble`, `createPlaylist`, `updatePlaylist`,
`deletePlaylist`, `createShare`.

Медиа: `stream` (с параметрами качества), `download`, `getCoverArt`, `getLyricsBySongId`, `getLyrics`.

Текст песни берётся из `getLyricsBySongId`: из нескольких вариантов выбирается синхронный, иначе
первый. Если структурированного текста нет вовсе, спрашиваем старый `getLyrics` по исполнителю и
названию — на серверах с простыми текстами это единственный способ их увидеть.

## Скробблинг

Отправляется `scrobble` с `submission=true` и `time` — временем начала прослушивания. Без сети
отметки копятся на диске и уходят, когда сервер снова доступен: по возрастанию времени, дошедшие
исчезают, недошедшие ждут дальше. Одно прослушивание засчитывается один раз — в том числе после
перезапуска, поэтому вместе с очередью сохраняется и текущее прослушивание
(`shared/cases/scrobbles.json`).
